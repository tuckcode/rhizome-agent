# Rhizome Trademark Policy

This policy covers the **Rhizome** name, logo, and related branding assets for **Rhizome Desktop**.

## Code license vs. trademarks

Rhizome Desktop source is licensed under the GNU Affero General Public License v3.0 or later (AGPL-3.0-or-later) — see [LICENSE](LICENSE).

That license applies to the **code**. It does **not** grant any right to use the Rhizome name, logo, or branding.

## Allowed without asking

You may, without prior permission:

- refer to Rhizome truthfully in commentary, documentation, blog posts, reviews, comparisons, or tutorials
- say that your project is based on, compatible with, or derived from Rhizome, as long as that statement is accurate
- redistribute unmodified official releases while preserving existing notices
- make nominative use of the Rhizome name to explain that you are discussing this project

## Not allowed without prior written permission

You may not, without prior written permission:

- use the Rhizome name or logo for a modified fork in a way that suggests it is the official project
- rebrand a hosted or commercial offering as "Rhizome" if it is not this project
- use the Rhizome logo in product branding, app icons, domains, marketing pages, or store listings for a fork or derivative product
- imply endorsement, affiliation, sponsorship, or approval by this project or its maintainer when none exists

## Forks and modified versions

If you fork or modify Rhizome Desktop once it's public, you're welcome to do so under the AGPL, but you must choose your own name and branding for any redistributed or hosted version unless you have written permission to use the Rhizome marks.

**Good examples**

- "Fork of Rhizome Desktop"
- "Based on Rhizome"
- "Internal knowledge app derived from Rhizome"

**Bad examples**

- calling your modified product "Rhizome"
- using the Rhizome logo for your fork
- presenting your hosted fork as the official Rhizome product

## Reservation of rights

All trademark rights in the Rhizome name, logo, and branding are reserved.

Questions or permission requests should be directed to the project maintainer.
