## Named-pipe leftover (non-blocking until boot works)

These are the open review notes from issue comments — worth knowing before trusting in the wild, but **not this window's work**:

1. **`WaitNamedPipeW` return value discarded** — comment argues `open` fails anyway; owner wants one log on real hardware to confirm it does not burn the full 3s timeout on every 4s poll when no daemon is running.
2. **`try_clone()` on duplicated pipe handle** — reader/writer split in `connect` and `read_roster_over`; not addressed by the roster fix and still untested against a live Windows daemon.
3. **Parked reader cannot be cancelled** — if daemon accepts then goes silent, one thread stays parked until daemon answers; `ROSTER_IN_FLIGHT` caps cost at one thread, not zero.
4. **Non-Unix, non-Windows targets no longer compile** — `#[cfg(not(unix))]` became `#[cfg(windows)]` for `DaemonStream` / `connect_stream`; theoretical (Tauri only ships unix + windows).
5. **Fake-daemon tests remain `#[cfg(unix)]`** — no Windows named-pipe server fake; manual verification against live daemon was always the planned first pass.
