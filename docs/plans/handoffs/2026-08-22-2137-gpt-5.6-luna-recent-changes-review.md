# Recent changes review — 2026-08-22

Scope: the current `main` range `19a83a9^..bb520e3`, covering the Chat
scrolling/link/native-chrome fixes, Prime steer/follow-up wiring, and the
pre-push environment helpers. No source changes were made by this review.

## Findings

### C43 — high: mid-turn fallback can lose the user's message

`AiPanel.tsx:324-333` and `:347-353` treat every `false` from
`sendToRunningTurn()` as “the turn ended; send normally.” The fallback closes
over `handleSend` from the render where `isActive` was true.
`useAiPanelController.ts:191-195` rejects that callback while `isActive` is
true, so a queue/steer race can silently drop the message. The same problem
applies when the command throws, because `primeTurnMessaging.ts:36-41`
converts errors into `false`.

Fix direction: distinguish “Prime explicitly did not queue” from transport
failure, and make the normal-send fallback consult current status rather than
the stale active-render closure. Add an integration regression test that
starts active, resolves the queue command as false, then verifies a new turn
is sent.

### C44 — high: the Rust queue command ignores Prime's queue result

`prime_session_host.rs:1278-1283` returns `true` whenever `host.call()` succeeds.
Prime's `follow_up` response carries `{ queued }` in its `data`
(`~/.local/lib/node_modules/prime-agent/dist/modes/daemon/daemon-mode.js:3475-3500`),
but the Rust code discards it. The frontend can therefore clear the input and
display a queued item when Prime rejected it during the race this feature says
it handles.

Fix direction: return `data.queued` for follow-ups, preserve the existing
success semantics for steer, and test both `{ queued: true }` and
`{ queued: false }` through the command boundary.

### Follow-up: pre-push browser helper does extra work

`.husky/pre-push:81-85` uses `playwright install --dry-run` as a condition.
That command exits successfully while only printing install metadata, so the
real install command runs on every local fallback push. It is not a product
failure, but it adds an avoidable environment check/install attempt. Replace
it with an installed-browser check or document the intentional cost.
