## Issue comments (Atticus, 2026-09)

Three comments refine the original issue body. Build order and precedence:

| Case | Trigger | Mechanism | Status |
|---|---|---|---|
| **Case 1 — pills** | Agent ends in a closed question | Parse the agent's own written options → 2–4 pills | **Shipped** |
| **Case 1 — ghost** | One obvious continuation, no closed question | Rules-first `{ kind: 'completion' }`; Tab accepts | **Shipped** |
| **Case 2** | No question, but app state suggests a move (unpushed commits, failed gate, session turning) | Model call and/or state-derived phrasing | **Parked — do not build** |

**Precedence (issue comment 3):** when both pills and ghost could apply, **pills win; never both on the same turn.**

**Safety rule (comments 1–3):** anything that causes an action must name the action — `"Push 33 commits"`, never `"yes"`. Pills may carry approvals because they must be aimed at; ghost text still must not be a reflexive approval.

**Case 2 quote (issue comment 2):** *"Harder, needs judgment about when to stay silent, and worth far less than case 1. Do not let it block case 1 from shipping."*
