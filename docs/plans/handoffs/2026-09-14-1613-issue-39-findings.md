## What shipped (#39 parts)

Five tools in `src-tauri/src/vault/graph_queries.rs`, exposed via
`rhizome_api::graph_query`, `call_rhizome_tool`, `rhizome-tool graph-query`,
and MCP:

| Tool | Role |
|---|---|
| `rhizome_graph_health` | One-call vault shape (notes, links, orphans, dead links, hubs) |
| `rhizome_graph_orphans` | Worklist; `total` + `truncated` |
| `rhizome_graph_dead_links` | Grouped by unwritten target, most-wanted first |
| `rhizome_graph_neighbors` | Subgraph within N hops; edges among nodes for UI |
| `rhizome_graph_path` | Shortest path between two notes |

All built on **`build_graph`** — same graph the graph view draws. **No Python
`rhizome-graph` fallback** on these paths (by design).

## C40 — `rhizome_graph_summary` vs in-repo graph

**C40-OPEN** in `docs/HANDOFF.md`: external `rhizome-graph` CLI disagreed with
`build_graph` (144 vs 155 pages, 84/64 vs 174 edges, no uncreated targets, slug
collapse, useless `communities`). Orphans and dead links **cannot** be derived
from the CLI.

### Fixed (MCP stdio path)

Commit **`a61374e`**: `mcp-server/index.js` — `handleRhizomeGraphSummary` now
delegates to `handleRhizomeGraphHealth` / `graph-query health`. Description
updated (dropped unreliable `communities`). Regression tests in
`mcp-server/test.js` pin same argv and same sidecar-required error when
`RHIZOME_TOOL_PATH` is unset.

### Leftover (still on external CLI)

| Path | File | Behavior |
|---|---|---|
| Tauri `call_rhizome_tool` | `src-tauri/src/rhizome_commands.rs:104–107` | Still `run_cli(["rhizome-graph", "summary", vault])` |
| WS bridge executor | `mcp-server/ws-bridge.js:179–192` | Still `execFileSync('rhizome-graph', ['summary', …])` |

So Prime calling graph tools through **stdio MCP** gets the in-repo graph;
callers hitting **Rust dispatch** or **ws-bridge** can still get C40 wrong
numbers. `ARCHITECTURE.md` § scoped graph queries still describes summary as
shelling out to the CLI — stale for MCP, accurate for Rust/ws-bridge.

**Do not invent a new MCP tool.** The five #39 tools plus `rhizome_graph_health`
are the surface. C40 cleanup is **align or retire `rhizome_graph_summary`** on
the remaining paths (same `graph-query health` delegation as MCP, or deprecate
the name in favour of `rhizome_graph_health`) — not add a sixth query verb.
