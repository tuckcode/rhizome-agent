# #46 findings — Chat-without-vault vs MCP HOME scope

**Origin:** Cursor Grok 4.6 · 2026-09-14 16:05 · findings only.

## Plain answer

Two different things share the word “home.” Chat with no vault attached is
**supported** — Prime’s working folder may be `$HOME`. That is not the bug.
The bug is treating `$HOME` **as a vault**, which would seed
`~/.prime/agent/settings.json` (Prime’s global config) and point vault MCP
tools at the whole home tree.

## What #46 reported

When `vault_path` resolves to the home directory, `prime_vault_skill.rs`
writes MCP config to `vault_path/.prime/agent/settings.json`, which for
`$HOME` **is** `~/.prime/agent/settings.json`. Two failures:

1. **Scope.** `VAULT_PATH=~` scopes every vault MCP tool
   (`search_notes`, `create_note`, `get_note`, …) to the entire home
   directory.
2. **Clobbering.** Rhizome mutates Prime’s global settings as a side effect
   of a path that looked vault-local.

Owner comment (2026-08-29): a pre-guard global skill at
`~/.prime/agent/skills/rhizome-vault/SKILL.md` also named `$HOME` as the
vault root, contradicting the system prompt. That stale copy was removed
manually. The guard stops new writes; it does not retroactively detect old
poison. Connect-time scrub only removes a Rhizome-authored global skill
(`cli-call.mjs` + Rhizome body in `SKILL.md`).

## Chat-without-vault (supported, not MCP scope)

`normalize_cwd("")` in `src-tauri/src/prime_session_host.rs` returns
`dirs::home_dir()` when `vaultPath` is blank. That is **Chat-without-vault**:
Prime gets a sane cwd; Rhizome does **not** seed vault tools because
`looks_like_vault($HOME)` is false and `seed_vault_skill` no-ops.

`PrimeSessionHost::connect` still calls `scrub_poisoned_global_home_vault_skill()`
on every connect (leftover from before the guard), then attempts seed only when
cwd passes `looks_like_vault`.

Documented in `docs/CROSS-MODEL-HANDOFF.md` §23. **Do not “fix” cwd** by
inventing a sandbox or rewriting Prime’s global settings.

## MCP HOME scope (refused)

Defense in depth landed locally (`4416411`, atop `e90e37c`):

| Layer | Behavior |
|---|---|
| `looks_like_vault` / `is_home_directory` | HOME, `~/`, symlink-to-HOME never count as vaults |
| `seed_vault_skill` | Skips HOME; refuses global settings collision |
| `save_vault_list` | Rejects HOME roots |
| MCP bridge (`lib.rs`, `mcp.rs`) | Drops HOME from `VAULT_PATHS`; validates refuse HOME |
| `mcp-server/vault-path.js` | `isHomeVaultPath` uses `realpathSync`; CLI rejects HOME |
| Connect scrub | Removes only Rhizome-authored global `rhizome-vault` skill |

Nested vaults under home (e.g. `~/Documents/Rhizome Vault`) still work.
