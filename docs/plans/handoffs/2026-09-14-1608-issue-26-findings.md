# Issue #26 — Rhizome green bar vs Prime updater leftover

**Origin:** Cursor Grok 4.6 · 2026-09-14 16:08 · read-only findings.  
**Issue:** [#26 Update Prime from inside Rhizome, as one Rhizome Agent update](https://github.com/tuckcode/rhizome-agent/issues/26) — open, `ready-for-agent`, no comments.

## What #26 asks for

One user-facing concept: **"a Rhizome Agent update."** Detection is done (#19); install is not. Acceptance criteria require one-click in-app install (no GitHub page, no terminal), copy that never names Prime as a separate product, consent-gated (not silent), safe behaviour while a turn is streaming, version refresh without restarting Rhizome, and PostHog events. Issue body notes `prime-agent update [--force]` already exists in Prime but Rhizome has never called it.

## Two update surfaces today (Rhizome only on the bar)

| Surface | File | Drives | Prime? |
|---|---|---|---|
| Full-width bottom **UpdateBanner** | `src/components/UpdateBanner.tsx` | `useUpdater` → Tauri `app_updater.rs` | **No** — Rhizome-only; blue bar, green restart button when `ready` |
| Status-bar **VersionUpdateIndicator** (package icon + green dot) | `src/components/VersionUpdateIndicator.tsx` | Both `useUpdater` and `usePrimeUpdate` | **Yes** — one badge, modal splits Rhizome vs Prime |

`App.tsx` wires both from the same `updateStatus` / `updateActions` pair for Rhizome, plus `primeUpdateStatus` / `primeUpdateActions` for Prime. Comment at line ~1331: *"#19: one indicator covering both Rhizome and Prime."*

Manual **Check for updates** (build-number button next to theme toggle) calls `handleCheckForUpdates`, which only invokes `updateActions.checkForUpdates()` — **Rhizome only**. Prime is checked separately on a 3 s timer inside `usePrimeUpdate` once `primeHostStatusForUpdates?.version` is known.

## Prime updater leftover (#19 half-shipped)

**Backend (`src-tauri/src/prime_update.rs`).** Module doc states deliberate policy: *"only ever reports an available version"* — no download, install, or restart. `check_prime_update` compares daemon handshake version against GitHub Releases (`PrimeIntellect-ai/prime-agent`). No Rust command wraps `prime-agent update`; repo grep finds zero references to that CLI from Rhizome code.

**Frontend (`src/hooks/usePrimeUpdate.ts`).** Auto-check after 3 s when `primeVersion` is set. On available: stores release URL; `openPrimeReleasePage` opens GitHub externally. Comments explicitly document why Rhizome cannot safely run install (unknown install path: npm, Homebrew, mise, asdf, manual binary). **No install action exists** on `PrimeUpdateActions`.

**UI (`VersionUpdateIndicator.tsx`).** Badge shows when *either* Rhizome or Prime is `available` (single green dot — `var(--accent-green)`). Modal contradicts #26:

- Separate headings: `versionUpdate.rhizomeHeading` → "Rhizome {version}", `versionUpdate.primeHeading` → **"Prime {version}"**
- Rhizome "Update now" → `rhizomeActions.startDownload()` (real Tauri flow)
- Prime "Update now" → `primeActions.openPrimeReleasePage()` only
- Footnote: `versionUpdate.primeNeverAutoUpdates` — tells user Prime never auto-updates and sends them to the release page

Tests in `VersionUpdateIndicator.test.tsx` encode this as intentional current behaviour (Prime section named, GitHub open, "never updates automatically" copy).

## Gap vs #26 acceptance criteria

| #26 requirement | Current state |

| One Rhizome Agent update (Prime invisible) | Modal names Prime; two sections when both available |
| One click installs — no GitHub | Prime path opens GitHub only |
| `prime-agent update` wired to button | Not wired anywhere |
| Version refreshes without Rhizome restart | No post-install handshake refresh path |
| Streaming-session safety | Undecided / untested |
| PostHog offered / accepted / failed | Not present on Prime path |
| Copy in `en.json` | Keys exist but expose "Prime" (`versionUpdate.primeHeading`, `primeNeverAutoUpdates`) |

## Relationship to Rhizome green bar

Owner preference (learned): Rhizome's own in-app update path (green bar / update control), not Prime's updater. In code:

- **UpdateBanner** is the Rhizome download/restart strip; Prime never appears there. Backend still stubbed / no signed feed (see `2026-09-07-0000-composer-in-app-update-path.md`).
- **VersionUpdateIndicator** green dot is the *combined* availability signal; Prime availability can light the same dot even when Rhizome is up to date — user opens modal and still sees Prime as a separate product.

So the "leftover" is not dead code: it is the shipped #19 detection + GitHub-delegation UI sitting beside the Rhizome-only banner and check-for-updates control, **blocking** #26's unified story until Prime install is in-app and copy/UI stop naming Prime.
