## Doctrine claim (ADR-0168)

Sources: `docs/design/harness-doctrine.md`, `docs/adr/0168-selective-harness-doctrine.md`

- **One sentence:** “Rhizome absorbs metabolites, not organs.” Prime is the only execution core (`harness-doctrine.md` §One sentence).
- **Frankenstein test:** *If we deleted Prime tomorrow, would this piece still try to run?* Yes → organ → do not transplant (`harness-doctrine.md` §The Frankenstein test).
- **Lineage lock (Execution):** Prime “may not become a Rhizome-owned runtime or **second provider path**” (`harness-doctrine.md` §Lineage locks).
- **Explicit reject list:** “every second runtime, **credential store**, scheduler, memory authority…” (`0168-selective-harness-doctrine.md` §Decision).
- **Prime owns:** “providers, credentials, model catalog and session model state” (`harness-doctrine.md` §Source verdicts → Prime Agent).

**Internal tension inside the ADR itself:** Consequences say *“The inherited `ai_models.rs` provider path may remain for non-Prime Desktop leftovers, but it is **rejected as an architectural path for Prime chat**.”* (`0168-selective-harness-doctrine.md` §Consequences, lines 76–77). The doctrine text forbids the path; the ADR consequences acknowledge it and bound it — they do not reconcile code with the Frankenstein test or lineage lock.

## Partial guard — Chat canvas only

`src/components/ChatHome.tsx` (`:82–91`): when `defaultAiAgent === 'prime'`, an `api_model` default target is **coerced back to the Prime agent** so Chat keeps Prime chrome. Comment: *“A direct API model chosen as the global default must not strip Prime chrome or route chat away from Prime.”*

Regression lock: `src/lib/parked-organs.test.ts` (`:236–246`) asserts this guard stays in source.

**Scope of the guard:** Chat home only. The `api_model` path remains wired for Research/Distill/Import fallback, Settings provider configuration, title generation, and any surface that resolves a non-Prime default or explicit `api_model` target. The guard reduces Prime-chat bypass; it does not remove the second path.

## Contradiction map (findings only)

| Layer | Doctrine says | Code does |
|---|---|---|
| Execution | Prime only; no second provider path | Rhizome HTTP client + tool loop in `ai_models.rs` / `ai_model_tools.rs` |
| Credentials | Prime owns provider credentials | Rhizome `ai-provider-secrets.json` + env lookup |
| Model catalog | Prime `models.json` / daemon | Rhizome `aiModelProviderCatalog.json` + user-configured `ai_model_providers` in settings |
| Prime Chat | Core chat depends only on Prime | **Guarded** in `ChatHome.tsx` — api_model default coerced to Prime |
| Other surfaces | Doctrine rejects path “for Prime chat” (ADR consequence) | Research fallback, workspace chip, title gen still use `api_model` |

**Net:** Constitution (`harness-doctrine.md` lineage lock + Frankenstein test) and code disagree. ADR-0168 consequences partially acknowledge the path but do not resolve the contradiction for non-Chat surfaces or the Frankenstein test. Issue #56 is filed so this stays on the record; **no reconciliation commit exists** in the tree audited here.
