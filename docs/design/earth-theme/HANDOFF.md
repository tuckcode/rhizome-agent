# Earth theme: implementation handoff

**For:** whoever wires the approved Earth palette and accessibility fixes into the app.
**Lives at:** `docs/design/earth-theme/` next to `DESIGN.md`, `colors_and_type.css` and `contrast_check.py`.
**Decision (2026-10-10):** Earth dark is the default dark theme, Earth light is the light theme, and Loam is an optional extra dark theme. The product name goes back to **Rhizome**; the repo, bundle ids and package names stay `rhizome-agent` for now, so don't rename them as part of this work.

This is design input, not a code change. Values below are final; component work is described, not prescribed line by line.

## 1. Where the tokens live in the app

| File | What it holds | What to do |
|---|---|---|
| `src/index.css` | The app's own light/dark contract. Light is `:root, [data-theme="light"]` (about lines 37–188); dark is `:root.dark, [data-theme="dark"]` (about lines 189–339). It uses app token names (`--surface-app`, `--text-primary`, `--accent-blue` …), not the design-system names. | Replace the color values per the table in §2. Keep every token name. |
| `src/themes.css` | Fixed color themes (Dracula, Nord, Everforest …). **Auto-generated by `scripts/generate-themes-css.mjs`; don't edit by hand.** | Add Loam as a new theme in the generator's source data, then regenerate. |
| `src/lib/themeMode.ts` | `COLOR_THEMES` registry (slug, name, polarity, swatch); `DEFAULT_COLOR_THEME = 'rhizome'` means "use the `index.css` contract". | Add `{ slug: 'loam', name: 'Loam', polarity: 'dark', swatch: ['#15110C', '#1D1811', '#6FE3A0'] }`. Keep `rhizome` as the default. |
| `src/theme.json` | Editor theme; its colors are already `var(--…)` references. | No change needed. |
| `colors_and_type.css` (design system) | Design-system token names (`--bg`, `--fg`, `--muted` …) for mocks and artifacts. | Replace with the file in this folder. |

## 3. Behaviour changes that come with the palette

These are in `DESIGN.md` §6–7. Where each one lives today:

1. **Busy composer stays usable.** `src/components/AiPanelChrome.tsx` sets `composerDisabled = (isActive && !canSteer) || agentReadiness !== 'ready'` and passes `disabled` down to the composer input (`WikilinkChatInput` / `InlineWikilinkInput.tsx`). While a run is active the input must stay focusable and editable. Send becomes Stop; Enter steers when `onSteer` exists, otherwise the text is queued or held until the run ends. Keep blocking only when the agent isn't ready, and say why in the placeholder.
2. **Focus ring everywhere.** `:focus-visible` = 2px solid `--border-focus` (or `--state-focus-ring`), offset 2px, including the contenteditable composer and plain text areas. Search for `outline-none` / `outline: none` on inputs (e.g. `AddPropertyForm.tsx`, `ColorInput.tsx`, `components/ui/*`) and make sure a visible ring replaces it.
3. **Live regions for run status.** The transcript gets `role="log"` with `aria-live="polite"`, and a streaming message gets `aria-busy`. Add one visually hidden `role="status"` that announces tool start and finish, completion, stop and approval needed, throttled. Some `role="status"` uses already exist (`ChatComposerFoot.tsx`, `ChatPreflightBanner.tsx`); reuse that pattern.
4. **11px minimum for informational text.** There are about 38 `text-[10px]`, 4 `text-[10.5px]` and 3 `text-[9px]` uses (e.g. `CommandRail.tsx` badge, `NoteItem.tsx`, `WorkspaceInitialsBadge.tsx`). Raise anything a user has to read to 11px; 10px only for decorative kickers.
5. **Status text uses the status tokens directly** (`--accent-green` / `--feedback-success-text`, `--feedback-warning-text`, `--accent-red`). They're text-safe now, so remove any one-off darker variants. Expected states like "needs vault" are warn, not error.
6. **One mint per view.** Audit the agent mark, brand mark, chips and selected rows. Selected rows use `--state-selected` plus a 2px accent bar, the same in light and dark.
7. **Naming in UI copy:** "Rhizome" in titles, the About window and onboarding. Leave repo-facing strings alone.

## 4. How to verify

1. Run `python3 docs/design/earth-theme/contrast_check.py docs/design/earth-theme/colors_and_type.css`. It prints every text token's ratio against `--bg` and its worst ratio across all surfaces, status text on its tinted fill, and `--border-input` on bg and surfaces. It exits non-zero on any failure.
2. For app-only tokens (syntax, diff, type accents), point the same functions at the values in `src/index.css`, or spot-check with any WCAG contrast tool. Text must be at least 4.5:1 on `--surface-app`, `--surface-panel`, `--surface-popover`, `--surface-button` and `--surface-sidebar`.
3. Run axe (or the in-app a11y check) on the chat view in each scheme. Expect zero `color-contrast` violations.
4. Visual check against `compare.png` and `compare-dark-warm.png` from the palette review.
5. Keyboard: Tab into the composer during a run (it must take focus and show the ring), type, press Stop, and confirm a screen reader hears "Run started / tool finished / complete".
