## Findings and recommended order

### F01 / C89: Align the first splash with the selected theme

**Priority:** P1. **Basis:** Reproduced browser behavior.

With only `rhizome-theme=dark` saved, the HTML splash selected light mode and a white background.
The React splash then selected dark mode and background `rgb(31, 30, 27)`.
The controlled transition trace records both states in one navigation.

`index.html:99-102` reads older theme, color-theme, and accent keys.
`src/constants/appStorage.ts:2` and `src/lib/themeMode.ts:115-119` define the current keys and legacy fallbacks.
The bootstrap also uses background colors that differ from the main theme surfaces.

**Recommendation:** Use the current keys first, with the same legacy fallback order as the application.
Resolve mode, named theme, accent, and initial background before visible content appears.
Do not remove legacy compatibility.

**Acceptance:** The HTML splash, React splash, and application agree for light, dark, system, and named themes.
Test current-only keys, legacy-only keys, conflicting keys, and unavailable storage.

Evidence: [Splash measurements](2026-10-04-ui-audit/splash.json), [transition trace](2026-10-04-ui-audit/transition.json).
Images: [HTML with saved dark mode](2026-10-04-ui-audit/splash-html-dark.png), [React dark mode](2026-10-04-ui-audit/splash-react-dark.png).

### F03 / C89: Prevent the splash animation from restarting

**Priority:** P2. **Basis:** Reproduced with controlled loading delays.

The HTML stage ran the branch and node animations.
When React replaced it, all corresponding animation times returned to zero.
The probe delayed the main request by 700ms and the application request by 1200ms.
Those delays expose the transition. They are not startup performance measurements.

Owner: `src/main.tsx`, `src/components/BootSplash.tsx`, `src/components/BootSplash.css`.

**Recommendation:** Keep one animation timeline across both stages, or let only the HTML stage perform the entrance animation.
Do not delay application readiness to complete an animation.
Reduced-motion probes reported zero animations in all six measured splash cases.

**Acceptance:** A delayed load does not replay the entrance motion. Reduced motion remains static.

Evidence: [Transition trace](2026-10-04-ui-audit/transition.json), [static splash matrix](2026-10-04-ui-audit/splash.json).

### F04 / C90: Make dark variants follow the application theme

**Priority:** P1. **Basis:** Reproduced component behavior.

The semantic tokens follow the application theme.
The tested Tailwind `dark:` background follows the operating-system color preference instead.
A destructive Button therefore receives different opacity for the same application theme when the operating-system preference changes.

| Operating-system preference | Application theme | Observed destructive background |
|---|---|---|
| Light | Light | Opaque red |
| Light | Dark | Opaque light red |
| Dark | Light | Red with 60% alpha |
| Dark | Dark | Light red with 60% alpha |

Owner: `src/index.css`, `src/components/ui/button.tsx:13-14`.
A source search found no custom dark variant in the source CSS.

**Recommendation:** Bind Tailwind dark variants to the application's resolved theme selector.
Review sibling controls that use `dark:` before changing the shared rule.
Then correct destructive text contrast for the resulting background.

The calculated dark destructive contrast is 3.423:1 on `surface-panel` under the 60% alpha assumption.
The mounted component confirmed that alpha treatment when the operating-system preference was dark.
The contrast number uses sRGB alpha compositing of the source token values. It is not a screenshot pixel measurement.

**Acceptance:** All four combinations use the intended application treatment.
Normal button text reaches at least 4.5:1 on its actual background.

Evidence: [Four-case matrix](2026-10-04-ui-audit/mode-matrix.json), [contrast calculations](2026-10-04-ui-audit/measurements.json), [mounted component](2026-10-04-ui-audit/assets.json).

## Design suggestions, not defect claims

### Typography and control density

Keep Inter for reading and interface text.
Keep IBM Plex Mono for code and genuinely technical values.
Keep JetBrains Mono for the wordmark.

The chat body measured 13px with 20.8px line height and a 644px reading column at the wide viewport.
Try a 14px chat body with about 1.6 line height before considering another family.
Compare long replies side by side before approval.
Do not increase the root size globally without checking every rem-based control.

Composer labels measured 11px. Model and thinking controls measured 22px high.
Tools and context controls measured 21px high. The vault trigger measured 18px high with 10px text.
These measurements support larger targets, but they do not alone prove a WCAG target-size failure.
Spacing exceptions and neighboring targets still need assessment.

**Recommendation:** Try 12px consequential labels and 28–32px primary control targets.
Use muted metadata only when users can still read it comfortably.
Reserve uppercase overlines for a clear reason. The reference prefers sentence case.

Owner paths: `src/components/PrimeModelPicker.tsx:258-275`, `src/components/PrimeSessionList.tsx:347`, `src/components/ChatComposerDeck.tsx`, `src/components/StatusBar.tsx`.
Evidence: [Control measurements](2026-10-04-ui-audit/survey.json), [reading measurements](2026-10-04-ui-audit/rich.json).

### Fonts and offline behavior

The model chip used IBM Plex Mono online and Consolas with remote font requests blocked.
That change is verified for the chip, not every text surface.

**Recommendation:** Consider local Inter and IBM Plex Mono files if consistent offline rendering is important.
Check licensing, required weights, and production bundle size first.
Do not synthesize font files or assume the archive supplies those families.

Evidence: `fonts` in [measurements](2026-10-04-ui-audit/measurements.json).

### Colors and contrast

The default body and secondary text tokens have strong measured contrast against `surface-app`.
The light muted and faint tokens do not meet 4.5:1 for normal text.

| Token | Light contrast | Dark contrast |
|---|---:|---:|
| `text-primary` | 13.238:1 | 15.600:1 |
| `text-secondary` | 6.851:1 | 9.002:1 |
| `text-tertiary` | 4.971:1 | 6.593:1 |
| `text-muted` | 3.622:1 | 4.763:1 |
| `text-faint` | 2.389:1 | 3.099:1 |

**Recommendation:** Preserve the palette. Correct token use and added opacity where important text becomes difficult to read.
Do not classify every muted token as a defect. Verify each visible use and its actual background.

A worker incorrectly called `--primary: var(--accent-blue)` a broken accent binding.
The live red-accent probe changed `--primary` to `#E8837C`, matching `--accent-red`.
Reject that worker finding. The default alias does not prevent later overrides.

### Logos and artwork

Keep the six-node in-app mark and Signal native icon family.
The favicon deliberately uses four thick spokes for small-size clarity. Its source explicitly documents that simplification.
Do not report it as an accidental missing satellite.

The native mark has more internal detail and more margin than the favicon.
A small-size raster review is useful, but the enlarged 32px raster is not evidence of a shipping scaling defect.

**Recommendation:** Preserve context-specific variants and document their allowed size ranges.
Keep the organic root illustration on About and marketing surfaces.
Avoid texture in the chat transcript and editor.

Owner paths: `public/favicon.svg`, `src/components/BrandMark.tsx`, `src-tauri/icons/icon-source.svg`.
Evidence: [Asset comparison](2026-10-04-ui-audit/brand-assets.png), [About](2026-10-04-ui-audit/settings-nav-settings-section-about.png).

### Splash visual treatment

The shaded mark and compact card create a distinct startup treatment.
The warm charcoal background differs from the green-black working surfaces.

**Recommendation:** Align backgrounds first. Then compare a softer card shadow with the current treatment.
Preserve the mark and wordmark. Do not add a progress percentage without a real progress source.
The archive restricts added mark effects, so retain shading only as an explicit splash exception.

### Model menu and action hierarchy

The model menu includes a full Thinking list.
The adjacent Think control opens the same level choices.
The repeated controls increase menu density without adding another capability.

**Recommendation:** Keep model selection in the model menu and thinking selection in its adjacent control, unless a unified control replaces both.
Preserve access to model-list editing and search.
This is a proposal, not an approved navigation change.

Evidence: [Model menu](2026-10-04-ui-audit/model-picker-loaded.png), [Thinking menu](2026-10-04-ui-audit/thinking-loaded.png).

### Notes and narrow layouts

The sampled narrow layouts did not produce horizontal page overflow.
The 480px layout collapsed navigation and secondary content.
Notes at 834px remained usable as a dense list, but titles and snippets truncated.
A partially visible final row in a scroll area is not, by itself, a clipping defect.

**Recommendation:** Test explicit Notes and reading modes for sustained editing rather than permanently giving every panel equal width.
Improve discovery of the existing Notes restore control before adding another navigation destination.
A richer keyboard, resize, and scroll review remains necessary.

Evidence: [834px Notes](2026-10-04-ui-audit/notes-834.png), [480px shell](2026-10-04-ui-audit/notes-480.png), [open note](2026-10-04-ui-audit/note-editor.png).
