# Rhizome Agent window: design critique (2026-10-10)

**Who and why:** A developer running Prime against a local vault. They ask a question, watch tools run in the thread, check what was read or written, and save what's worth keeping. Every frame should make three things obvious: what Prime is doing, what it touched, and what you can do next.

- **Source:** `rhizome-agent-desktop-ui.html`, all six frames (A Working, B Note split, C Save to vault, D No vault, E First run, F Sessions), checked in Mycelium and Ledger.
- **Judged against:** `DESIGN.md` and its tokens. Accessibility is out of scope here; I refer to those findings by ID from `2026-10-10-a11y.md` (B1–B5, W1–W11, M1–M13).
- **Evidence:** every frame rendered in Playwright at 1440×900 (reduced motion on, so the frames are static) in `design/`, plus a count of mint (`--accent`) elements per frame, the measured transcript/note-pane split, and an audit of every spacing, radius and font-size value in the CSS.

**Totals:** 2 blockers · 12 worth fixing · 13 minor

| Frame | Mint elements in window | Rule (DESIGN.md §2) |
|---|---|---|
| A Working | 13: brand mark, rail current, "Prime session live" text and dot, working dot, agent mark, pending marker, PENDING, spinner, caret, Prime chip, busy footer text ×2 | 2 at most |
| B / C / D | 6 each (D also has two solid primary buttons) | 2 at most |
| E First run | 5, plus the ASCII art and a radial mint glow | 2 at most |
| F Sessions | 5 | 2 at most |

## Blockers

**D-B1 · Interaction and states · Frame F: the selected session and the main pane disagree.** The sidebar highlights "Promote vs auto-distill · Today 14:08", but the main pane shows the new-chat empty state ("Ask Prime to research, search your vault…"). You can't tell which conversation you're in, or whether the old one was lost.
*Fix:* a selected session shows its own transcript. Show the empty state only for a new chat, with a "New chat" row selected using `--state-selected` (a11y W6/W7 cover the selected-row styling).

**D-B2 · Copy / states · Frame C: the save confirmation contradicts itself.** The tool card created `inbox/20260809-promote-vs-distill.md`, titled "Promote vs auto-distill". The toast says "Saved ‘Kernel notes’ to the vault". "Save to vault" stays active afterwards, and the subhead says "promote complete". You can't trust what was saved, and you can save twice.
*Fix:* the toast repeats the real title and folder and offers an action: "Saved “Promote vs auto-distill” to inbox/ · Open". After saving, the button becomes a disabled "Saved" with a check in `--ok`. Use one verb everywhere (see D-W8).

## Worth fixing

**D-W1 · Color · The "one mint accent" rule is broken in every frame (13 hits in A).**
*Fix:* keep mint for the rail's current item plus one other thing: Send when idle, or the run-status chip when busy. Brand mark → `--fg-tertiary`. Agent mark → `--muted` dot. Prime chip → default chip (`--border`, `--fg`). Busy footer → `--fg-secondary`. Pending marker → hollow. Caret → `--fg`. First-run step numbers → `--muted`. Remove the `.onboard` radial `--accent-dim` glow.

**D-W2 · Color / hierarchy · Frame D has two solid primary buttons (Attach vault and Send).** That is anti-pattern 7.
*Fix:* make the empty-state "Attach vault" `.btn-save` (accent text on `--accent-dim`) and drop the duplicate in the titlebar. Send stays the one primary.

**D-W3 · Hierarchy · Frame D says "no vault" seven times.** The titlebar chip and button, the subhead "memory tools locked", the empty-state badge and button, the tool card LOCKED, the error box, the composer chips "No vault" and "Skills · (vault off)", and the footer "Degraded · memory off".
*Fix:* say it once in the empty state (with Attach vault) and once in the composer chip (dashed `--warn`). Remove the titlebar, subhead and footer copies.

**D-W4 · Interaction and states · Frame D: an expected state looks like an error.** It uses `--danger` throughout (red marker, LOCKED, red box), and offers Retry, which can't succeed without a vault.
*Fix:* tool status reads "needs vault" in `--warn` text with a hollow marker. Replace the error box with an inline note (`--warn-bg`, dashed `--warn` border like `.chip.locked`) whose action is "Attach vault". Remove Retry.

**D-W5 · Layout · Frame B splits 50/50, but DESIGN.md §5 says conversation gets at least 55%.** Measured: transcript 50.0%, note 50.0% (`.main.split { grid-template-columns: 1fr 1fr }`).
*Fix:* `grid-template-columns: minmax(0, 3fr) minmax(320px, 2fr)` (60/40), with a resizable divider that stops at 55%.

**D-W6 · Hierarchy · The chrome repeats the same facts.** The vault "Laputa" appears 3× (titlebar chip, subhead path, composer chip). The last tool `get_note` appears 3× (titlebar chip, tool card, footer). The model appears 2×. Shortcut hints appear twice and disagree: the subhead says "⌘. stop", the footer says "Esc stop · ⌘.".
*Fix:* titlebar = brand + one run-status chip + New chat. Subhead = session id, model and vault path (read-only telemetry). Composer chips = only what you can change (model, vault, skills, as real buttons per a11y B5). Footer = one shortcut hint.

**D-W7 · Interaction and states · Frame A's status count is wrong.** It says "Running tools · 2" while the timeline shows 1 done and 1 pending, and "Open" is enabled on the pending `get_note`.
*Fix:* "Running tools · 1", or "Tools 1/2". Disable Open until the tool finishes (DS disabled state, opacity 0.42), or only show it on done cards.

**D-W8 · Copy · Notes to the designer are showing up as product copy.** Frame B's subhead says "note open · secondary" and "chat remains visible — no editor takeover". Frame E says "No multi-agent picker." Frame F shows the "Chat → tools (search/read/create) → Promote/Save → …" diagram. "Promote" and "Save to vault" are mixed for the same action.
*Fix:* remove the annotations. Use "Save to vault" as the single verb in the UI and keep "promote" for docs, or rename the button "Promote to vault" everywhere. Either way, pick one and list it in DESIGN.md §8.

**D-W9 · Interaction and states · Frame D keeps its empty state above the conversation.** The empty state stays after messages exist.
*Fix:* show the empty state only while the transcript is empty. After that, use a slim inline banner at most.

**D-W10 · Interaction and states · Frame E's first run has broken and missing states.**
- Opening the app straight onto First run leaves a blank 100px ASCII box. The script calls `show()` before `framesAscii` and `asciiEl` exist; I confirmed `#ascii-rhizome` is empty on direct load and filled when you click the tab.
- The footnote shows the raw placeholder "Prime connected: — · session: —".
- "I've logged in — recheck" has no checking or result state.
- The titlebar uses error red ("Prime not found") for a normal first run.

*Fix:* define the frames before calling `show()` and render the last frame statically. Footnote: "Not connected yet". Recheck → a busy "Checking…" state with an inline result. Titlebar chip: neutral or `--warn` "Prime not connected".

**D-W11 · Spacing · About 80 spacing values are off the 4px scale.** Values found: 5, 6, 7, 9, 10, 11, 13, 14, 18 and 22px. Examples: bubble 11/13, tool row 8/10, composer 10/14/12, message gap 7, transcript 22. DESIGN.md itself lists 18, 22 and "6–10".
*Fix:* snap to `--space-*`: bubble 12, tool row 8/12, composer 12/16, message gap 8, transcript 24/32, `--gap-msg` 16 or 20. Update DESIGN.md §4 to match.

**D-W12 · Type · There are 15 font sizes: 8, 9, 9.5, 10, 10.5, 11, 11.5, 12, 12.5, 13, 13.5, 15, 18, 22 and 26px.** The token scale is 10, 11, 12, 13, 14, 16, 20, 26. Message text is 13.5px against the DS 13px body, and `.btn` uses weight 510.
*Fix:* map them onto the tokens. 13.5 → 13 (`--font-size-base`). 12.5 → 12. 11.5 and 10.5 → 11. 8, 9 and 9.5 → 11 (a11y W10). 15 → 16. 18 → 20. Weight 510 → 500.

## Minor

- **D-M1 · Frame C:** the toast floats about 300px below what it confirms, and its "OK" label adds nothing. *Fix:* anchor it above the composer or right under the message actions, use a check icon in `--ok`, and add Open and Undo.
- **D-M2 · Frame C:** the message actions start with Regenerate. *Fix:* order them Copy · Save to vault · Fork, with Regenerate in an overflow menu.
- **D-M3:** the tool card Open button is ghost in A but default in B and C. *Fix:* use `.btn-sm` default everywhere.
- **D-M4 · Frame F:** there are two "New chat" + buttons (titlebar and session header). *Fix:* show one, in the session header while that pane is open.
- **D-M5 · Frame F:** session meta mixes a time with a status ("Working · tools"), and there's no grouping or row menu. *Fix:* "14:08 · working", group under Today / Earlier kickers, and add a ⋯ menu on hover.
- **D-M6 · Frame F:** the titlebar chip "Prime · sess_7f2a" has an inline 10px size, and the session id sits in the subhead in every other frame. *Fix:* keep it in the subhead only.
- **D-M7 · Radius:** controls use `--r-sm` 6px, but DESIGN.md §6 says buttons are 8px. *Fix:* change `.btn` to `--radius`, or change the DS to say 6px for controls.
- **D-M8 · Glyphs:** the thinking disclosure uses the text glyphs ▸/▾, and the rail has a vertical "CHAT" hint. *Fix:* use a 12px stroke chevron SVG and remove the hint (a11y M5).
- **D-M9 · Tool cards:** they don't say what happened. "done" has no result count or duration. *Fix:* path text like "“promote vault” · 3 notes · 120ms" in `--muted`.
- **D-M10 · Fonts:** the mock loads Inter and JetBrains Mono from the Google Fonts CDN and requests JetBrains Mono 500, while the DS only bundles 600 (`.tool-name` is 500). *Fix:* bundle the fonts locally for offline Tauri use, and use 600 or bundle 500.
- **D-M11 · Composer textarea:** it's user-resizable and shows a grip. *Fix:* grow automatically up to 140px with `resize: none`.
- **D-M12 · Frame E copy:** "Install Prime" doesn't say it opens outside the app, and "I've logged in — recheck" is clumsy. *Fix:* "Install Prime ↗" and "Check again".
- **D-M13 · Harness:** the frame A annotations sit over the transcript and can't be hidden. *Fix:* add an "Annotations" toggle to the harness.
