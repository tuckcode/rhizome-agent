# Knowledge graph ("Wiki Graph" / "Node map"): design critique (2026-10-10)

**Who and why:** A developer with a growing vault opens the map to answer one of three questions:
1. "What is this note connected to?"
2. "Where are the clusters and the orphans?"
3. "What should I read or link next?"

They want to get from a node to something they can read in one or two moves, without losing their place.

- **Sources:** `image-1.png` (dark theme, about 1024pt wide) and the current graph source in `app-src/src/components/graph/*` and `hooks/useGraphKeyboardNav.ts`.
- **Screenshot vs code:** the screenshot predates the current layout. It shows search and filters at the top left and an "Exit graph" button. The code puts search and filters bottom-right, the legend bottom-left (collapsed), and labels the button "Back to chat". Each finding below says which one it was checked against.
- **Evidence:** `annotated.png`, crops `crop-*.png`, and a panel-overlap simulation (`sim-panels.html`, results `sim-panels-*.png`) that rebuilds the `GraphControls` and `GraphLegend` size limits at five canvas sizes.

**Totals:** 5 blockers · 9 worth fixing · 5 minor

## The current key map, verbatim from the code

`hooks/useGraphKeyboardNav.ts` is a `window` keydown listener with `enabled: true` and no focus scoping. It is skipped only when the target is an input, textarea, select or contenteditable.

| Input | What the code does |
|---|---|
| `ArrowUp` / `ArrowDown` / `ArrowLeft` / `ArrowRight` | `if (!focusedId) return`, so nothing happens until a node is selected. Otherwise it moves the selection to the **direct neighbour** whose projected screen position lies furthest along that direction (`nextNodeInDirection`; neighbours behind the direction are skipped). Then it calls `flyToNode(id)`, which moves the camera to 120 units from the node along the origin→node ray over 600ms. |
| `Enter` | `if (!focusedId) return`. Otherwise `onOpen(focusedId)` opens the note (`preventDefault`, so it also swallows Enter on any focused button). |
| `Escape` | Progressive: leave local graph (ego), otherwise clear the selection, otherwise `onExit()` (leave the graph). |
| Click a node | `selectNode`: sets the selection and opens the preview dock. **No camera move.** |
| Click the background | Clears the selection. |
| Mouse drag / right-drag / wheel | 3d-force-graph defaults (`trackball`): rotate / pan / zoom. `showNavInfo(false)` hides the library's own help text, and nothing replaces it. |
| Hover | `nodeLabel` tooltip shows the title. This is the only way to read a node's name on the canvas. |
| On-screen hint | `graph.legend.controls`: "Arrows move · Enter opens · Esc backs out" (inside the collapsed Key). |

## Blockers

**G-B1 · Interaction · You can't get into the map with the keyboard.** Arrows and Enter return early while `focusedId` is null, and nothing selects a first node. The hint "Arrows move" does nothing on arrival. *Fix:* on open, select the most-linked node in view, or the note you came from. Show its ring and preview, and make the hint "↑↓←→ next linked note".

**G-B2 · Interaction · The arrow-key selection isn't visible on the canvas.** `colorForNode` is `resolver.colorFor(node.isA, node.ghost)` and never reads `selectedId`, so the effect that re-runs on selection change paints the same colours. The only feedback is the camera lurching and the preview changing. *Fix:* draw the selected node with a 2px `--accent` ring at 1.6× scale, keep its first-degree edges at full opacity, and fade everything else to 0.25.

**G-B3 · Interaction · The arrow keys change meaning after every press.** Direction is computed in screen space, but each move flies the camera along a new origin→node ray, so the scene rotates under you. "Left" then "Right" often doesn't return to where you started. This is the "rotating with the movement keys isn't intuitive" complaint, and it comes from this design. *Fix:* keep the camera orientation fixed on keyboard moves and only pan or translate to keep the node in view (see the 2D recommendation below). Make click and keyboard behave the same: today a click doesn't move the camera at all.

**G-B4 · Interaction · The window-level listener steals keys from the rest of the app.** It's always `enabled: true` and checked against `window`. With the graph open in the Connections panel beside the notes:
- Arrow keys pressed in the note list or the chat history, which aren't editable fields, move the graph selection and call `preventDefault`.
- Enter on a focused button (Exit, a filter pill, "Local graph") opens the selected note instead.

*Fix:* attach the listener to the canvas host (`tabIndex=0`, `role="application"`, labelled "Wiki graph, N notes") and only handle keys when focus is inside it. Let buttons handle their own Enter.

**G-B5 · Layout · In the screenshot, the window controls sit on top of the search field.** "Find a note…" starts at x≈52pt, under the red, yellow and green buttons, so a click aimed at search can close or minimise the window. The current code moved search to the bottom right, so check this on the build. *Fix:* any top-anchored overlay starts below the 28px titlebar drag region, or to the right of the traffic lights (`left: 80px`).

## Worth fixing

**G-W1 · Hierarchy · The preview doesn't help you decide what to read.** `NodePreviewPanel` shows a type dot, title, snippet, `isA` badge, project badges, a relative date, "N links · N backlinks", Local graph, and Open note. Reading anything means Open note, which leaves the graph. *Fix:* see "What the preview should show".

**G-W2 · Layout · The auto-fit frames the outliers, not the content.** `framePreservingMinimumDistance` runs `zoomToFit` on mount, on every data change, and again on `onEngineStop`. It fits all 143 nodes, including about 20 isolated dots and ghosts, so the main cluster fills about 25% of the canvas. The second fit also yanks the camera after the user has moved it. *Fix:* fit the largest connected component with 10% padding, fit once, and never refit after user input. Put orphans in a separate "Unlinked (n)" list.

**G-W3 · Visual design · 3D costs more than it gives here.** Depth carries no meaning: z is a physics artifact. It causes occlusion, makes direction ambiguous (G-B3), forces rotation as a navigation step, and costs WebGL. *Fix:* use 2D by default (see below). If you keep 3D, make it an opt-in "Orbit" toggle.

**G-W4 · Layout · The overlay panels cover too much of the map.** Simulated with the code's size limits:

| Canvas | Area covered with both panels open | Panels overlapping each other |
|---|---|---|
| 784×860 (full window + dock) | 20% | none |
| 600×560 | 31.5% | none |
| Compact sidebar 420×520 | 37.6% | 19,968px² |
| Compact sidebar + preview | 39.6% | yes |

*Fix:* move search and filters into one 36px toolbar strip above the canvas (not floating), and make the Key a popover from that toolbar. Nothing should float over the canvas except zoom buttons, bottom-right, 28px each.

**G-W5 · Copy · The exit button and Escape don't match where you came from.** The exit button says "Back to chat" (`graph.exit`) even when you came from Notes or a note's context menu. The screenshot says "Exit graph". A third Escape leaves the view. *Fix:* "Close graph" (or "← Notes" / "← Chat" from the real origin). Escape clears the local graph, then the selection, and stops there. Closing the view is ⌘W or the button.

**G-W6 · Hierarchy · Nodes have no labels.** Titles only appear on hover, so you can't read the map without hovering every dot. *Fix:* always label the selected node and its neighbours, label the top ~12 nodes by degree when zoomed out, and label everything above zoom 1.5. Use 11px Inter in `--fg-secondary` on a `--bg` halo.

**G-W7 · Color · 17 note types share about 6 hues, and the 4 edge colours can't be told apart.** In the screenshot's Key, concept, Note, Operation, Project, source and Task are all orange or red. Edges at 1.5px width and 0.7 opacity are indistinguishable at that size. *Fix:* colour only the 6 most common types and show the rest as `--muted` "Other". Draw edges in one neutral (`--border-strong`) and put the relationship kind in the preview, not in the edge colour. Wikilinks solid, belongs-to dashed if you need a distinction.

**G-W8 · Hierarchy · The type list appears twice.** It's in the filter pills and in the Key. *Fix:* make the Key list the filter, with each row a checkbox (dot + name + count). Drop the pills.

**G-W9 · Hierarchy · Ghosts and orphans add noise.** In the screenshot, 32 "not created" nodes are scattered as noise, and hiding ghosts isn't the default. *Fix:* hide ghosts by default and add a "Show 32 unwritten links" toggle in the Key.

## Minor

- **G-M1:** type names are raw `isA` values with mixed casing (Untyped, concept, entity, Event, plugin). *Fix:* sentence-case the display labels.
- **G-M2:** the hint "Arrows move · Enter opens · Esc backs out" wraps, is vague, and sits hidden inside a collapsed Key. *Fix:* put a one-line hint in the toolbar: "↑↓←→ linked notes · ↵ open · Esc clear".
- **G-M3:** the feature has four names: "Wiki Graph" (`graph.title`, rail, palette), "Graph" (Connections tab), "Node map" (context menus) and "Exit graph". *Fix:* use one name. I suggest "Graph" (see app-navigation A-W2).
- **G-M4:** `nodeVal = 1 + links + backlinks` with no cap, so hubs dwarf everything. *Fix:* use `nodeVal = 1 + sqrt(degree)`, clamped to 6.
- **G-M5:** there's no mouse help (`showNavInfo(false)`). *Fix:* add "Drag to pan · scroll to zoom" to the hint.

## How I'd restructure it

**The job:** for a developer, the graph is a way to find what to read next, not a screensaver. The questions are "what's around this note", "what's isolated", and "where are the dense topics". So the map should start from a note, show its neighbourhood clearly, and make reading one step away.

**1. Go 2D and local-first.**
- Open on the current note's local graph, 2 hops deep. "Full graph" is a toggle.
- Use a 2D force layout that freezes after it settles (d3-force or `force-graph`, the 2D sibling with the same API), so positions stay stable while you navigate. 3D becomes an opt-in "Orbit" toggle at most.
- No rotation. The mouse drags to pan and scrolls to zoom (zooming at the cursor), like Figma.

**2. A key map that's spatially honest and doesn't depend on the camera:**

| Key | Action |
|---|---|
| (on open) | Selects the origin note, or the top hub in Full graph |
| `↑ ↓ ← →` | Next linked note in that direction. The camera pans only; it never rotates. |
| `Tab` / `Shift+Tab` | Cycle the selected note's neighbours, sorted by link strength. Works with screen readers. |
| `Enter` | Open the note in the editor **beside** the graph (split), and keep the graph open |
| `⌘Enter` | Open full width and close the graph |
| `Space` | Show or hide the reading preview |
| `L` | Toggle local graph (`Shift+L` for depth 1↔2) |
| `F` or `/` | Focus "Find a note…" |
| `0` | Fit to the main cluster |
| `+` / `-` | Zoom |
| `Esc` | Clear the local graph, then the selection. Stops there. |
| `⌘W` or the toolbar ✕ | Close the graph |

All keys are scoped to a focused canvas (`role="application"`). The full list goes in the ⌘/ Keyboard Shortcuts sheet under "Graph".

**3. What the preview should show (a docked right panel, 320px, resizable):**
- Title with type (dot + label) and folder path in mono `--muted`.
- The first about 600 characters of rendered body, or the note's first section. Real Markdown, not a one-line snippet.
- **Why it's connected:** "Linked from" and "Links to" lists, grouped by edge kind, each with its context sentence (the line containing the `[[wikilink]]`). Clicking a row selects that node on the map. This is the main value the graph can add over the editor.
- Outline (H2/H3) as jump links into the note.
- Actions: **Open beside** (primary) · Open · Local graph · Copy link. For ghosts: "Create note" plus the list of notes that reference it.
- Modified date and project chips go in a single `--muted` meta line, not badges.

**4. Layout (sketch):**
```
┌ Graph ─ [Local ▾ 2 hops] [Find a note… /] [Types ▾] [Key ▾] ─────── [0 Fit] [✕] ┐
│                                                         │ ● concept · notes/rag/  │
│        (2D map, labels on neighbours,                   │ Karpathy's LLM Wiki…    │
│         selected = mint ring, rest dims)                │ first section rendered… │
│                                                         │ Linked from (5)         │
│                                                         │  ↳ Grok Wiki Plan — "…" │
│                                              [+][-]     │ [Open beside] [Open] …  │
└─ ↑↓←→ linked notes · ↵ open beside · Esc clear ───────────────────────────────────┘
```
